# Mero Restro Print Agent

A small local background service that lets the Mero Restro web app
(`https://app.merorestroapp.com`) print receipts and kitchen tickets to a
thermal printer physically connected to a restaurant's own computer (USB or
LAN), using raw ESC/POS commands. The remote Laravel backend never touches
the printer — this agent runs entirely on the restaurant's machine and is
the only thing with physical access to it.

```
React POS (app.merorestroapp.com)
        │  https fetch to http://127.0.0.1:<port>
        ▼
Print Agent (this project, running locally)
        │  raw ESC/POS bytes
        ▼
USB / LAN
        ▼
ZKTeco ZKP8018 (or any ESC/POS 80mm thermal printer)
```

## Why a separate project

The web app is hosted remotely; the printer is not. There is no way for a
remote server to reach a USB device on someone's counter, so printing has
to be initiated from software running on that same computer. This agent is
that software — a tiny HTTP server bound to `127.0.0.1` only, so it's
reachable from the browser tab open on that computer but not from the
internet or other machines on the network.

## API

| Route | Auth | Purpose |
|---|---|---|
| `GET /health` | none | Is the agent running, and on which port. |
| `GET /printers` | none | List printers this computer already has installed. |
| `POST /print` | pairing token | Print a receipt or kitchen ticket. |
| `POST /test-print` | pairing token | Print a self-contained diagnostic slip. |
| `GET /jobs/:id` | pairing token | Look up a past print job's status. |

`/health` and `/printers` are read-only and don't require the pairing
token, so the frontend can detect the agent and populate a printer picker
before the user has connected it. `/print` and `/test-print` require the
`X-Print-Agent-Token` header — see **Security** below.

## Security

- Binds to `127.0.0.1` only — never `0.0.0.0`. Nothing outside this
  computer can reach it, regardless of firewall configuration.
- Every request's `Origin` header is checked server-side against an
  explicit allowlist (`https://app.merorestroapp.com`, plus localhost dev
  origins) — see `src/security.ts`. This is enforced on the request
  itself, not just via permissive CORS response headers, which only
  control what a browser lets its own JS *read* and wouldn't stop the
  request from executing.
- A random pairing token (generated on first run, stored in this
  computer's local config — see **Where files live** below) is required
  on every actual print request, as a second layer beyond origin
  checking.
- There is no endpoint that accepts arbitrary raw ESC/POS bytes from the
  caller — the agent only ever builds print jobs itself from structured
  receipt/kitchen-ticket data (see `src/escpos/`), so a compromised or
  malicious frontend origin can't use this as a generic "print anything"
  primitive even if it somehow got past the two checks above.

## Where files live

| OS | Config + log directory |
|---|---|
| Windows | `%APPDATA%\MeroRestroPrintAgent` |
| macOS | `~/Library/Application Support/MeroRestroPrintAgent` |
| Linux | `~/.mero-restro-print-agent` |

`config.json` holds the port the agent bound to and its pairing token.
`agent.log` is a plain-text log of every print attempt and failure — safe
to hand to a restaurant's IT support or paste into a support ticket.

## Development

```bash
npm install
npm run dev      # ts-node-dev, auto-restarts on save — headless, no Electron/tray
```

The agent tries ports `38111`–`38115` in order and prints which one it
bound to, along with its pairing token, to the console on startup.

To run it inside the Electron tray wrapper during development (closer to
what a customer actually gets, minus the installer):

```bash
npm run electron:dev   # builds src/ then launches Electron with a tray icon, no window
```

## Customer-facing installers (recommended path)

```bash
npm run build:mac      # -> release/Mero Restro Print Agent-<version>-universal.dmg
npm run build:win      # -> release/Mero Restro Print Agent Setup <version>.exe
```

These use [`electron-builder`](https://www.electron.build/) to produce a
real installer: the customer downloads it, runs it like any other app
installer, and the Mero Restro Print Agent starts automatically at login
as a menu-bar/tray app — no Node.js, npm, or Terminal ever required. See
`DEPLOYMENT.md` section "0.1" for the full packaging writeup.

`build/icon.png` is currently a **placeholder** (generated by
`node scripts/gen-placeholder-icon.js`) — swap it for real branding before
shipping to customers.

## Building a standalone executable (legacy / advanced use only)

```bash
npm run build          # tsc -> dist/
npm run package:win    # -> dist-pkg/mero-restro-print-agent-win.exe
npm run package:mac    # -> dist-pkg/mero-restro-print-agent-macos (x64 + arm64)
```

These use [`pkg`](https://github.com/vercel/pkg) to bundle Node.js itself
plus this project into a single executable, with no installer, tray icon,
or auto-start wrapper around it — kept for anyone who deliberately wants
the raw binary (e.g. running it under their own process manager) rather
than the Electron installer above, which is what customers should actually
receive.

**Windows raw USB printing note:** the `printer` package (an optional
dependency) wraps the Windows spooler's raw `WritePrinter` call so ESC/POS
bytes reach a USB printer untouched. It's a native addon, so `npm install`
must run on a Windows machine (or via `npm install --target_platform=win32`
cross-compilation tooling) to get a working prebuilt binary before
`npm run package:win`. Network (LAN, `host:port`) printing never needs this
— it's a plain TCP socket and works identically on every OS.

## Auto-start at login

```
scripts/install-windows-startup.ps1        # Windows — Startup-folder shortcut
scripts/install-macos-launchagent.sh       # macOS — LaunchAgent (~/Library/LaunchAgents)
```

Both are documented at the top of the script and are meant to run once,
after packaging, on the restaurant's own computer. See the main project's
deliverables document for the full install walkthrough aimed at a
non-technical restaurant user.

## Project layout

```
src/
  index.ts                    Express app + route wiring
  config.ts                   port selection, pairing token, persisted config
  security.ts                 origin allowlist + pairing-token middleware
  logger.ts / paths.ts        local logging + per-OS data directory
  printers/
    discovery.ts               lists OS-installed printers (no native deps)
    rawPrint.ts                 sends raw ESC/POS bytes (TCP / CUPS raw / Windows spooler)
  escpos/
    commands.ts                 low-level ESC/POS byte builder
    columns.ts                  80mm/58mm column-width text layout helpers
    receiptBuilder.ts           customer receipt (mirrors BillReceipt.tsx)
    kitchenTicketBuilder.ts     kitchen/bar ticket (no payment info)
    testPrintBuilder.ts         self-contained diagnostic test slip
  jobs/
    queue.ts                    job IDs, statuses, idempotency dedupe
  types.ts                      shared request/response shapes
```
